0Il principio

PostoCos'èCosa la cancella
File del progettoLa memoria vera: .claude/memory, context, rules, CLAUDE.md, AGENTS.md, _notes/Niente: né commit né wipe la toccano
Git e GitHubLa fotografia dei file a ogni milestoneNiente
ChatIl contesto di lavoro della sessioneChiusura o compattazione

Quindi: tutto ciò che nasce in chat va su disco nello stesso giro (lo fa l'agente), e ogni punto fermo va in git (lo decidi tu con chiudi). L'agente prepara, tu confermi: git add, commit e push non li esegue mai un agente.

1Una volta per macchina

  1. Comandi nel profilo: su Windows .claude/templates/agenti-terminale/tools/Installa-Comandi.ps1 installa claude-account<N>, codex-account<N> e chiudi; su Linux e macOS bash .claude/templates/tools/installa-chiudi.sh installa chiudi nel profilo Bash o Zsh. Poi apri un terminale nuovo. Un terminale già aperto non rilegge il profilo.
  2. Hook git attivi in ogni repository: git config --local core.hooksPath .githooks. Su Linux/macOS anche chmod +x .githooks/*. Senza, pre-commit e commit-msg non girano.
  3. Identità locale in ogni repository (user.name, user.email) e, una volta, git config --global user.useConfigOnly true. Git rifiuta di committare senza identità locale; chiudi si ferma prima.
  4. Wipe per account installato come hook SessionEnd (session-end-wipe.ps1 su Windows, session-end-wipe.sh su Linux e macOS). Si verifica con check-account-hygiene.ps1 o con la variante .sh.

2Apertura di una sessione

cd "E:/template-claude-developing"
claude-account2
  1. /status: conferma l'account. Un re-login può cambiarlo senza avvisare.
  2. /riprendi: confronta l'impronta dell'ultima chiusura con lo stato reale, poi legge memoria e punto di ripresa. Se la sessione precedente è caduta, te lo dice prima di costruirci sopra.
  3. /sync-context: segnala le schede rimaste indietro rispetto al codice.

Con Codex: codex-account2. Legge AGENTS.md, che gli fa fare la stessa ripresa e applicare le stesse regole.

3Durante il lavoro (automatico)

A ogni giro sostanziale, cioè quando nasce una decisione, una misura, una correzione, una pendenza o una fonte, l'agente scrive su disco nello stesso giro: memoria, schede, documenti, _notes/RESUME-PROMPT.md. Chiude ogni risposta con la riga File scritti.

Come controlli. Dopo un giro con contenuto nuovo deve esserci la riga "File scritti". Se manca, chiedila: quel contenuto è rimasto solo in chat. I giri di sola spiegazione non scrivono niente, perché non c'è niente di nuovo da salvare.

4Milestone: un blocco concluso = un commit = un chiudi

  1. Un blocco coerente è finito e verificato (una funzione, una correzione, una regola, un documento). L'agente scrive il messaggio in _notes/COMMIT-MSG.txt e ti dice: "milestone pronta: lancia chiudi", con il messaggio.
  2. Nel tuo terminale, dentro il progetto: chiudi.
  3. Leggi file, ramo, autore e messaggio; rispondi s.
  4. Continui a lavorare nella stessa chat. Il wipe si salta da solo perché la sessione è aperta: non si perde niente.

Due milestone nello stesso giro si propongono una alla volta. Nessun blocco concluso, nessun commit.

5Fine sessione

  1. L'agente ha già aggiornato RESUME-PROMPT.md e, se c'è lavoro da fissare, COMMIT-MSG.txt.
  2. Chiudi Claude o Codex. Il wipe lavora sui file che la sessione riscrive finché è aperta.
  3. Nel terminale: chiudi, poi s. Stavolta il wipe parte, su tutti gli account che hanno lo script installato.

Se c'è ancora un'altra sessione Claude aperta (un altro progetto, l'editor), il wipe viene rimandato e chiudi stampa i comandi da lanciare dopo. Niente di male: lo farà la prossima chiusura.

7Casi d'uso

quotidiano

Salvo e continuo

Milestone a metà: chiudi, s, e riprendi a scrivere nella stessa chat.

quotidiano

Fine giornata

Chiudi Claude, chiudi, s. Domani: claude-account2, /riprendi.

quotidiano

Solo verificare

chiudi -SoloControlli: vedi se è tutto verde senza committare.

errore

Un controllo è rosso

chiudi si ferma e mostra le ultime righe dell'errore. Incollale all'agente, che corregge; rilancia chiudi.

errore

Hook rifiuta il messaggio

Troppo lungo o con attribuzione. Chiedi all'agente un messaggio nuovo, oppure chiudi -Messaggio "…".

errore

Uscita 3

Commit e push sono fatti; l'impronta no (di solito manca _notes/RESUME-PROMPT.md). Alla riapertura /riprendi lo segnalerà.

errore

Push fallito

Rete o permessi. Il commit resta locale e l'impronta non si registra. Risolto il problema, rilancia chiudi: non ricommitta, pusha e registra.

errore

Identità mancante

chiudi si ferma. Imposta user.name e user.email locali del repository e rilancia.

rami

Ramo nuovo

git switch -c nome, lavori, chiudi: pusha con -u e collega il ramo remoto. Provato.

rami

HEAD staccato

chiudi si ferma subito: git switch <ramo> e rilancia. Provato.

rami

Repository senza origin

Commit locale, push saltato con avviso, impronta registrata. Provato.

ripresa

La sessione è caduta

Niente di perso su disco. /riprendi vede l'impronta vecchia e ti dice cosa manca; poi chiudi.

ripresa

Lavoro fatto altrove

git pull, claude-account2, /git-sync, /sync-context.

agenti

Uso Codex

codex-account2. Stesse regole da AGENTS.md: memoria a ogni giro, COMMIT-MSG, nessuna attribuzione. Chiusura identica: chiudi.

git

Commit di una parte sola

chiudi committa tutto. Per una parte, l'agente ti dà i comandi git per esteso (git add dei soli file, git commit -m, git push).

progetti

Progetto senza chiudi

chiudi dice che non è istanziato. Allinea il progetto: /riprendi, /gate-pacchetti.

wipe

Wipe rimandato

Altre sessioni Claude aperte. Chiudile e lancia i comandi stampati, o lascia fare alla prossima chiusura.

conferma

Ho risposto N

Niente committato. Correggi ciò che non ti convince e rilancia.

8Garanzie e limiti

Non può succederePerché
Commit senza la tua confermachiudi chiede [s/N]; gli agenti non eseguono git commit
Commit co-authored con un agenteHook commit-msg; storia verificata: 0 occorrenze
Commit con identità sbagliatachiudi si ferma; git ha useConfigOnly
Commit con controlli rossi o su HEAD staccatochiudi si ferma prima
Impronta su un push fallitochiudi verifica HEAD = remoto prima di registrare
Wipe della memoria di progettoIl wipe tocca solo la home dell'account, mai le cartelle di progetto
Limite. Si può perdere solo ciò che resta in chat senza essere scritto su disco. È il motivo della riga "File scritti".
